# Взгляд сверху · Ведическая астрология и Индия

Сайт двух экспертов по ведической астрологии, ягьям и турам в Индию.
Позиционирование: «Мы читаем вашу карту и ведём вас по ней — от консультации до поездки в места силы».

MVP по ТЗ (`ТЗ сайт «Ведическая астрология и Индия».md`): сайт, который принимает заявки.

## Стек

- **Nuxt 4** (Vue 3) + TypeScript
- **Nuxt UI 4** + **Tailwind CSS 4** — дизайн-токены «Ночной Варанаси»
- **GSAP + ScrollTrigger** и **Lenis** — богатая анимация и плавный скролл
- **Supabase** (self-hosted на VPS) — БД и заявки
- **Telegram Bot API** — мгновенные уведомления о заявках

## Разделы

Главная · Консультации · Ягьи (список + страница) · Туры (список + страница) ·
Обучение* · Журнал* · О нас · Правовые страницы

\* Обучение и Журнал — этап 2 (заглушки-лендинги с формой), чтобы навигация не вела в 404.

## Дизайн-система (ТЗ §5)

Токены в `app/assets/css/main.css`: `deep #151934`, `deeper #10132A`, `surface #2B3160`,
`line #4A5080`, `accent (шафран) #E3A857`, `ink/ivory #F4EDE1`, `muted2 #BDB4A4`.
Шрифты: Cormorant Garamond (заголовки) + Manrope (текст), Google Fonts с `display=swap`.
Фирменные элементы: арочные рамки (`ArchFrame`), кольцо накшатр (`NakshatraRing`),
силуэт храмов у реки (`TempleSilhouette`), звёздное небо (`StarField`).

## Анимация

- `app/plugins/animation.client.ts` — Lenis + синхронизация с ScrollTrigger, плавный скролл к якорям.
- `app/plugins/reveal.ts` — директива `v-reveal` (раскрытие по скроллу, каскад `{ stagger }`), SSR-safe.
- Hero на Главной — GSAP-таймлайн (арки, заголовок, параллакс кольца и силуэта).
- Всё уважает `prefers-reduced-motion`.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить SUPABASE_* / TELEGRAM_*
npm run dev            # http://localhost:3000
npm run lint           # ESLint (чисто)
```

## Окружение (`.env`)

| Переменная | Назначение |
|---|---|
| `SUPABASE_URL` | URL Supabase API (self-hosted, порт 8000) |
| `SUPABASE_KEY` | anon key (клиент) |
| `SUPABASE_SERVICE_KEY` | service_role — только сервер, для записи заявок в обход RLS |
| `TELEGRAM_BOT_TOKEN` | токен бота для уведомлений |
| `TELEGRAM_CHAT_IDS` | id чатов организаторов (через запятую) |
| `TELEGRAM_CONTACT` | ссылка на личку для кнопки «Написать в Telegram» |
| `INSTAGRAM_URL` | ссылка на Instagram |
| `YANDEX_METRIKA_ID` | id счётчика Метрики (цели `lead_*` на формы) |

## База данных

Схема — `supabase/migrations/0001_init.sql` (services, yagyas, tours, tour_days,
courses, articles, reviews, leads) с политиками RLS: контент читается всеми,
заявки может вставлять `anon`, читает их только сервер (service_role).

**Чтобы заявки начали сохраняться:** применить миграцию к Supabase на VPS
(SQL Editor в Studio или `psql`), затем задать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_IDS`.
Пока таблицы/токена нет, форма всё равно показывает экран «Спасибо» в dev, а сервер
пишет в лог, что заявка не сохранена.

## Заявки → Telegram

`server/api/lead.post.ts`: валидация → запись в `leads` → уведомление в Telegram.
Формы: консультация, участие в ягье, бронь тура, курс, лист ожидания. У каждой —
согласие на обработку данных и экран «Спасибо».

## Контент

Пока БД пуста, страницы берут данные-заглушки из `app/composables/useContent.ts`.
По ТЗ §8: реальные названия (божества, туры, эксперты), а цены/даты/«что входит» —
плейсхолдеры вида `[ЦЕНА]`, `[ДАТА 2026]`. Демо-даты ягий рассчитаны относительно
сегодняшнего дня, чтобы календарь был живым; заменяются реальными записями из БД.
